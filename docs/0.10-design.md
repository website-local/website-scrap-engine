# 0.10 design and development decisions

0.10 is unreleased. The lean implementation restores the 0.9.1 crawl and worker
architecture while keeping native URL handling, application-selected parsers,
correctness fixes and measured optimizations. Use the [migration guide](MIGRATION-0.10.0.md)
for API changes, the [URL guide](native-url-migration.md) for compatibility, and
the [GroveDOM guide](grovedom.md) for parser setup and ownership.

This document consolidates the development decisions and qualification through
2026-11-21. Historical experiment logs, evidence JSON, archived reports and
application-specific migration patches are no longer maintained here. Earlier
committed records remain available in Git history; this summary does not turn
failed or inconclusive experiments into successful ones.

## Architecture to preserve

- Keep lifecycle arrays, the full save-path callback, the three-argument pipeline
  constructor and the shared `parentPort` task/log protocol. Workers start only
  for processing; terminal streaming and local copies finish during download.
- Write directly to output. Publication coordinators, output reservations,
  outcome histories, admission/body budgets and staged writes were removed
  because they added default bookkeeping and filesystem work. Applications own
  conflict/publication policy; a failed direct write can leave partial output.
- Keep synchronous hook paths, coalesced worker dispatch, fair worker selection,
  URI reuse, duplicate-child filtering, callback I/O and zero-copy normalization.
  Actual worker resources retained faster property layouts with direct field
  assignments; do not add fields or caches merely to change a synthetic shape.
- A resource owns its body and active parsed document. It must not retain a
  downloader, pipeline, parent or child graph. Byte bodies are copied when a
  child is submitted during processing, so saving the parent cannot detach the
  child's bytes. Ordinary savers clear successful bodies and detach eligible
  complete backing stores after writes and pending observers finish. Failed
  saves retain bytes; pooled, partial, shared, protected and Wasm stores are not
  detached. No extra save hook or ownership registry is needed.
- Keep Cheerio lazy and honor supplied synchronous loaders in every nested parse.
  Each worker initializes its own application module. Managed documents are
  disposed after processing and pending status observers; queued caller-created
  documents remain caller-owned until execution begins.
- Preserve retry limits, cancellation, Retry-After, empty responses, HTTP 304,
  cache safety, stream range recovery, save policies and replacement ownership.
  Release failed admissions before error callbacks; count success and admit
  redirect aliases only after cleanup succeeds.
- Preserve request escapes and signed query bytes. Do not restore redundant
  decode/re-encode passes. Explicit file schemes are case-insensitive; target
  and referrer containment must survive encoded paths and source-root aliases.
  Keep bounded CSS/refresh parsing, positional replacements and literal `$`
  handling. Their malformed-input tests guard against polynomial backtracking.

## Dependencies and opt-ins

| Choice | Reason and limit |
| --- | --- |
| Got `~16.0.0`, locked 16.0.0 | Evaluated 13.0.0/15.0.0/15.1.0 fail credential contracts; no downgrade is adopted. |
| p-queue `~8.1.1`, locked 8.1.1; p-timeout 6.1.4 | Matches exact 0.9.1. Queue 9.3.5 is faster for 20,000 immediate queued tasks (elapsed ratio .319), but slower for bounded (1.493), yielding (1.182) and mixed-priority (1.136) work. Its large-backlog advantage is an accepted tradeoff, not a reason to replace queue 8. |
| Cheerio 1.2.0 | Default parser; load on first use. GroveDOM stays application-selected. |
| srcset 5.0.3 | Retain its grammar. log4js is an optional peer for file logging. |

Queue 8 spends backlog CPU shifting arrays; queue 9 adds running-task Map
records, timestamps and completion microtasks. Both assign IDs and have matching
promise counts. Do not infer a whole-crawl benefit from the backlog microbenchmark.

Native HTTP remains explicit through `httpTransport: 'native'`, with Got fallback
for unsupported settings. Default handlers perform no native dispatch or
initialization. Native setup still imports Got and constructs its Options; the
first initialization cost is about 1 ms plus a .1 ms snapshot. Repeated warm
construction costs about 17 microseconds. Exporting and reusing a prepared
configuration avoids rebuilding it when overrides are omitted; empty overrides
reconstruct it. Reuse shares mutable settings, hook closures and signals, does
not rerun init hooks, and does not refresh aborted signals. Keep factories when
independent state is necessary. No whole-crawl speedup from reuse was established.

### Optional Got formatter preload

```sh
node --import website-scrap-engine/lib/got-error-formatters.js app.mjs
```

Got's `@sindresorhus/is` dependency eagerly creates two `Intl.ListFormat` objects
for error messages. Native allocation traces and matched controls attribute
about 1.2 MiB live native memory and 3.5 MiB startup RSS to that work. The explicit
preload delays those constructors, preserves all 64 checked assertion outcomes,
and restores `Intl.ListFormat` synchronously. Enable it before the application
imports Got; already-loaded modules cannot benefit.

The preload is not imported by default. Automatic activation and a dependency
patch failed their speed qualification; neither is adopted. A no-op formatter
corrupts 41 checked error messages. The accepted helper is a memory option,
not a qualified default speed optimization or permanent global replacement.

## What caused the measured costs

| Source | Located work and decision |
| --- | --- |
| Dependencies | Got 16 creates nine URLs per streaming request versus one in Got 13 through sanitation and handler/hook snapshots. Diagnostics, empty-hook tracking, cookie helpers, response assembly and the formatter add work. Correctness blocks the evaluated downgrades. |
| Earlier 0.10 features | Publication messages, path checks, outcome/admission tracking and extra promise chains added default work. Lean removes them; do not restore the machinery implicitly. |
| Correctness fixes | Workers reconstruct URI methods lost by 0.9.1 cloning. Independent submitted byte bodies and document cleanup preserve ownership. These contracts must survive optimization. |
| Speed-oriented buffering | 256 KiB streaming batches reduce writes. Preserve them; smaller buffers need a demonstrated application benefit before adding a public option. |
| Parser initialization | Lazy Cheerio moves work from import to first HTML. Complete lazy/preload timings were inconclusive; the owner accepts the phase shift when complete timing is similar. A crawl-only delay histogram misses import work. |
| Memory accounting | Buffer sweeping, allocator pages, compiled code retained between collections, parser initialization and Got allocations all contribute. The full streaming RSS gap is not attributed exclusively to Got or batching. |

The save ownership fix reduced peak RSS by 20.2% for local workers, 14.6% for
local single and 10.9% for buffered workers versus preceding lean. Sampled
local-worker main ArrayBuffers fell 97.2%. These are workload-specific results,
not a sustained-memory guarantee. Some post-GC JS heap differences came from
compiled code retained when fewer collections occurred; production GC flags
and allocator trimming are not fixes.

## Performance qualification

The latest default lean/pre-lean panel compares pre-lean commit
`002149ed95b3727cd9d903d448ac61b50ff9b69e` with the lean implementation in commit
`0e75248bee87f8a22978c39161d64e2a77439a97` (final maintenance edits are comments).
Twelve balanced pairs per workload give 192 passing crawls,
319,488 exact files and 202,752 requests. Node 24.18/JIT, old-space 512 MiB,
semi-space 4 MiB, exclusive 45-second jobs and a sampled 2 GiB group stop were used.

Ratios below are lean/pre-lean geometric means with paired 95% log-t intervals;
below one means faster or less CPU. Complete timings include initialization,
ordinary workload and disposal; these are synthetic fixtures, not universal results.

| Workload | Elapsed ratio [95% interval] | CPU ratio [95% interval] |
| --- | --- | --- |
| Buffered single | .852 [.799,.910] | .803 [.758,.851] |
| Buffered workers | .817 [.752,.888] | .812 [.773,.852] |
| Streaming single | .961 [.893,1.035] | 1.001 [.922,1.088] |
| Streaming workers | .947 [.885,1.013] | .981 [.903,1.066] |
| Local single | .843 [.681,1.043] | .720 [.679,.763] |
| Local workers | .796 [.685,.926] | .713 [.675,.753] |
| HTML single | .970 [.909,1.035] | .921 [.864,.982] |
| HTML workers | .818 [.755,.886] | .805 [.744,.872] |

Four workloads pass both strict speed checks. Six metrics across the other four
remain inconclusive, with zero demonstrated aggregate slowdown. The streaming
CPU upper bound of 8.8% is not an observed 8.8% regression: its point estimate
is about .13% more CPU. No adverse aggregate phase interval establishes a slowdown.
The panel initially fixed arm order per workload; only unstarted blocks were
reversed after inspection, ending with six pairs per order. Preserve that
protocol deviation; all original observations, adverse pairs and zero CPU
readings remain included. No closed panel was rerun for clearance.

In the separate six-block default-versus-0.9.1 panel, all eight complete elapsed
and CPU intervals favored lean. In the same workload order, elapsed ratios were
.811/.812/.830/.768/.606/.732/.824/.792 and CPU
.677/.653/.883/.634/.554/.677/.793/.781. Streaming-single RSS was 1.062
[1.034,1.091]; speed is prioritized and identified buffering/dependency tradeoffs
are accepted, with residual memory attribution secondary.

Fresh streaming attribution verified 4,288 files with eight CPU profiles and
four operation traces. Both versions made 864 Got URLs and 96 engine URLs per
96 files, with equal request/open/writev/close counts. Lean created about 39%
fewer promises. Neither mode created processing workers for terminal streams.
An adverse profiled multi pair (1.031 elapsed/1.030 CPU) remains; profiled timing
does not replace the uninstrumented gate or establish a new aggregate regression.

These findings support local commits and package preparation. Formal universal
speed qualification remains open; application adoption and full-scale sustained
coverage are separate work. Functional success or a favorable point estimate
does not clear an inconclusive speed criterion.

## Closed experiments and unresolved observations

- Do not adopt private Got Request wrappers, cookie/init-hook shortcuts, automatic
  formatter activation, or native streaming/buffered import caching. They changed
  contracts or failed component/crawl gates. One combined caching experiment also
  had mismatched dependency layouts; its losses cannot all be assigned to source.
- The separate matching-layout buffered cache improved its target by about 6.4%,
  but local elapsed regressed 47.1% [5.1%,105.8%] and default buffered phase CPU
  7.8% [2.7%,13.1%]. Removing promises alone did not justify adoption.
- Two historical output-open `EINVAL` failures, local stalls around 193/232 ms,
  three markup gaps over 100 ms, and the optional native/preload local +4.17%
  result did not recur in focused follow-ups. Keep them deprioritized until a
  matching trace appears. No filesystem cause, repair or erasure is claimed.
- Native/preload factorial warmup costs and some cold-phase differences remain
  unattributed. Idle Node samples cannot distinguish storage, libuv scheduling
  and host preemption. Do not assign an old observation to an unrelated new gap.
- The public `URI.withinString` observer had an unresolved historical performance
  cost after complexity hardening; it is not used by the default crawler. Failed
  controls did not establish its non-regression. The URL guide retains the limits.

## Development rules and validation tools

Default performance must never regress, including in breaking releases. Costly
features must be explicit opt-ins with zero initialization, allocation,
bookkeeping or per-resource work when disabled. Preserve useful optimizations
while simplifying. Prefer elapsed/CPU speed over RSS-only improvements.

Measure fresh changes against the appropriate baseline with representative
workloads and exact output checks. Record versions and dependency layouts;
include startup, parser first use and disposal when claiming complete timing.
Use fixed balanced pairs; keep adverse observations, failures, zeros and outliers.
Use CPU/allocation profiles to locate causes, then verify a focused change without
profiling. Unreproduced observations are not active bugs. An unresolved observed
default slowdown blocks release; uncertainty is neither proof of a slowdown nor
proof of universal non-regression. Do not repeat closed panels until one passes.

Specific dependency and Node upgrade assumptions belong in comments beside the
affected function, with the relevant contract test. Keep this guide focused on
design choices, summarized results and development practice.

The retained scripts have distinct uses:

| Tool | Use |
| --- | --- |
| `copy-src.js` | Package build/prepack copies non-TypeScript source assets. |
| `package-lock-resolved.js` | Explicit npm `postshrinkwrap` hook normalizes mirror registry URLs. |
| `scripts/check-consumer.mjs CONSUMER` | CI/manual strict packed declarations and runtime smoke/TLS checks; `--grovedom` adds supplied-parser checks. Uses `scripts/fixtures/consumer.ts`. |
| `scripts/benchmark-crawl.mjs ENTRY [ENTRY...]` | Manual buffered/streaming/local/markup diagnostic in both modes, exact outputs and optional parent CPU profiles. Use `--expose-gc`; `WSE_BENCH_SAMPLES`, `WSE_BENCH_WORKLOADS` and `WSE_BENCH_MODES` bound the job. Imports are outside timing and the fixture server shares the process, so this is not the complete-process release gate above. |
| `scripts/stress-crawl.mjs [ENTRY]` | Manual repeated lifecycle, duplicate-admission, worker disposal and bounded retained-heap checks; use `--expose-gc`. It does not qualify sustained application memory. |

The script audit removed fifteen historical runners and six unreferenced root
probes tied to completed experiments, old filtered protocols or external corpora.
Relevant behavior remains in unit tests; future attribution should instrument
the actual reproduced workload instead of restoring obsolete campaigns.

Keep the four `test/runtime-*.js` checks (smoke, native HTTP, supplied parser,
formatter imports), four worker fixtures (delay, echo, error, exit-on-task),
the CommonJS import fixture, and ESLint/Jest configs. They exercise current
contracts; absence of a package-script entry does not make a test unused.

Before committing runtime changes, build, lint, check strict source/test types,
run the complete unit suite and check a packed consumer, including custom workers
and optional paths affected by the change. Use available toolchains; distinguish
installed development dependencies from a fresh locked install. Do not silently
rebuild a primary consumer or include unrelated drafts in a package.

The 2026-11-21 commit checks passed build, strict source/test types, 48 suites /
1,220 tests and lint (one existing type-import warning). The 261-file package
passed strict declarations, main/worker/custom-worker, TLS, eight parser cases
and ten formatter import scenarios. Final maintenance comments preserve parsed
source, emitted JavaScript and declaration syntax. The retained benchmark and
stress tools checked 960 and 384 saved files/resources respectively; these were
tool checks, not new performance qualification. Validation used existing Node
24.18/JIT, TypeScript 6.0.3, ESLint 10.11.0 and ts-jest 29.4.14; the latter two
differed from the then-locked 10.14.0/29.4.15. Later upstream lint-tool updates
were rebased without installing or validating the new toolchain. No fresh
installation or closed timing panel was run, and primary builds/dependencies
and downstream data were preserved.

Put temporary builds, copies, caches, profiles, outputs and runner receipts under
`/mnt/e/temp/` for this workspace, and delete all task-created artifacts when
finished. Keep only finished code and a concise useful summary. No retention
exception applies to evidence; preserve unrelated pre-existing work.

The local-history cleanup assessed all four `.local-evidence` campaigns. Useful
parser ownership/compatibility and unresolved URI observer findings are folded
into the two topic guides. The 2,354 generated/history files (about 62.5 MiB) and
ten links were removed; linked external targets were preserved. None was tracked
or needed by current builds/tests. No obsolete parser binary, package, source
snapshot or filtered benchmark protocol is retained as current qualification.
